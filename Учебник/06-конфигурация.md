## 6.1. `DatabaseConfig.java` — подключение к БД

### Зачем нужен

Обычно Spring Boot **сам** создаёт DataSource из `spring.datasource.url`. Но у нас нюанс: переменная `DATABASE_URL` приходит в формате:
```
postgres://username:password@host:5432/dbname
```

А JDBC требует другой формат:
```
jdbc:postgresql://host:5432/dbname
```

Поэтому мы пишем свой `DataSource`-бин, который сам конвертирует строку.

### Полный код

```java
package com.lingua.api.config;

import com.zaxxer.hikari.HikariConfig;
import com.zaxxer.hikari.HikariDataSource;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Primary;

import javax.sql.DataSource;
import java.net.URI;

@Configuration
public class DatabaseConfig {

    @Bean
    @Primary
    public DataSource dataSource() throws Exception {
        String dbUrl = System.getenv("DATABASE_URL");
        if (dbUrl == null || dbUrl.isBlank()) {
            throw new IllegalStateException("DATABASE_URL environment variable is not set");
        }

        if (dbUrl.startsWith("postgres://") || dbUrl.startsWith("postgresql://")) {
            URI uri = new URI(dbUrl);
            String host = uri.getHost();
            int port = uri.getPort() > 0 ? uri.getPort() : 5432;
            String path = uri.getPath().replaceFirst("^/", "");
            String userInfo = uri.getUserInfo();
            String user = "";
            String password = "";
            if (userInfo != null) {
                String[] parts = userInfo.split(":", 2);
                user = parts[0];
                password = parts.length > 1 ? parts[1] : "";
            }
            dbUrl = String.format("jdbc:postgresql://%s:%d/%s", host, port, path);

            HikariConfig config = new HikariConfig();
            config.setJdbcUrl(dbUrl);
            config.setUsername(user);
            config.setPassword(password);
            config.setMaximumPoolSize(10);
            config.setConnectionTimeout(30000);
            return new HikariDataSource(config);
        }

        HikariConfig config = new HikariConfig();
        config.setJdbcUrl(dbUrl);
        config.setMaximumPoolSize(10);
        return new HikariDataSource(config);
    }
}
```

### Разбор

```java
@Configuration
public class DatabaseConfig {
```
`@Configuration` помечает класс как «источник бинов». Spring обработает методы с `@Bean` внутри.

```java
    @Bean
    @Primary
    public DataSource dataSource() throws Exception {
```
- `@Bean` — Spring вызовет этот метод один раз при старте, сохранит результат и будет раздавать его всем, кому нужен `DataSource`.
- `@Primary` — «если есть несколько `DataSource`-бинов, считай этот основным».
- Имя бина — по умолчанию = имя метода (`dataSource`).

```java
        String dbUrl = System.getenv("DATABASE_URL");
        if (dbUrl == null || dbUrl.isBlank()) {
            throw new IllegalStateException("DATABASE_URL environment variable is not set");
        }
```
Читаем переменную окружения. Если её нет — падаем сразу с понятной ошибкой. Это лучше, чем «неясная NullPointerException где-то в недрах».

```java
        if (dbUrl.startsWith("postgres://") || dbUrl.startsWith("postgresql://")) {
            URI uri = new URI(dbUrl);
            String host = uri.getHost();
            int port = uri.getPort() > 0 ? uri.getPort() : 5432;
            String path = uri.getPath().replaceFirst("^/", "");
            String userInfo = uri.getUserInfo();
```
Парсим URL стандартным `java.net.URI`. Это тот самый класс, который умеет разбирать любой URL на компоненты.

```java
            String[] parts = userInfo.split(":", 2);
            user = parts[0];
            password = parts.length > 1 ? parts[1] : "";
```
Логин и пароль идут через двоеточие в `userInfo`. `split(":", 2)` означает «раздели по первому двоеточию» (важно — пароль может содержать двоеточие).

```java
            dbUrl = String.format("jdbc:postgresql://%s:%d/%s", host, port, path);
```
Собираем JDBC-URL. `%s` — вставка строки, `%d` — вставка числа.

```java
            HikariConfig config = new HikariConfig();
            config.setJdbcUrl(dbUrl);
            config.setUsername(user);
            config.setPassword(password);
            config.setMaximumPoolSize(10);
            config.setConnectionTimeout(30000);
            return new HikariDataSource(config);
```

**HikariCP** — самый быстрый пул соединений на JVM (входит в Spring Boot по умолчанию).

Что такое пул? Открыть соединение с БД — это медленно (~50 мс). Если на каждый HTTP-запрос открывать новое — пользователи будут ждать. Пул держит **10 уже открытых соединений** и переиспользует их. Когда запрос приходит — берём из пула, выполняем SQL, кладём обратно.

Параметры:
- `maximumPoolSize=10` — макс. 10 соединений с БД одновременно.
- `connectionTimeout=30000` — ждать соединение из пула не дольше 30 сек, иначе ошибка.

## 6.2. `AsyncConfig.java` — пул потоков для фоновых задач

### Полный код

```java
@Configuration
public class AsyncConfig {

    @Bean(name = "translationExecutor")
    public Executor translationExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);
        executor.setMaxPoolSize(8);
        executor.setQueueCapacity(50);
        executor.setThreadNamePrefix("translation-");
        executor.initialize();
        return executor;
    }
}
```

### Разбор

```java
@Bean(name = "translationExecutor")
```
Бин с явным **именем**. Имя пригодится позже: на методах с `@Async("translationExecutor")` мы говорим Spring «запусти меня в потоке из ЭТОГО пула».

```java
ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
executor.setCorePoolSize(4);
executor.setMaxPoolSize(8);
executor.setQueueCapacity(50);
```

Параметры пула потоков:
- **corePoolSize = 4** — пул всегда держит 4 потока «наготове».
- **maxPoolSize = 8** — при пиковой нагрузке может довести до 8.
- **queueCapacity = 50** — если все 8 потоков заняты, новые задачи копятся в очереди (макс. 50).
- Если очередь переполнена — Spring выбросит исключение.

```java
executor.setThreadNamePrefix("translation-");
```
Имена потоков будут `translation-1`, `translation-2` и т.д. Это видно в логах — удобно отлаживать.

```java
executor.initialize();
```
Без этого пул не запустится. Часто забывают.

### Зачем вообще пул

Перевод книги — медленная операция (минуты). Если делать его в HTTP-потоке, Tomcat будет «занят» им и не сможет принимать другие запросы. Поэтому мы запускаем перевод в отдельном пуле потоков, а HTTP-ответ возвращаем мгновенно.

## 6.3. `CorsConfig.java` — разрешаем кросс-доменные запросы

### Что такое CORS

Браузеры по умолчанию **запрещают** JavaScript на одном домене (`example.com`) делать запросы к другому домену (`api.example.com`). Это защита от плохих сайтов.

Чтобы разрешить — сервер должен прислать специальные заголовки `Access-Control-Allow-Origin` и т.д. Это и есть CORS.

В нашем случае:
- Фронт `bilingual-reader` живёт на `/`.
- API `api-server` живёт на `/api`.
- Технически это один домен (всё проксируется через один порт), но если делать запросы из других мест — нужно разрешить.

### Полный код

```java
@Configuration
public class CorsConfig {

    @Bean
    public WebMvcConfigurer corsConfigurer() {
        return new WebMvcConfigurer() {
            @Override
            public void addCorsMappings(CorsRegistry registry) {
                registry.addMapping("/**")
                        .allowedOriginPatterns("*")
                        .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                        .allowedHeaders("*")
                        .allowCredentials(false);
            }
        };
    }
}
```

### Разбор

```java
registry.addMapping("/**")
```
Применить CORS-настройки **ко всем путям**. `**` — wildcard.

```java
.allowedOriginPatterns("*")
```
Разрешить запросы с **любых** доменов. Для продакшена обычно лучше указывать конкретные:
```java
.allowedOriginPatterns("https://lingua.example.com")
```

```java
.allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
```
Какие HTTP-методы разрешены.

```java
.allowedHeaders("*")
.allowCredentials(false);
```
Любые заголовки, без cookies. Если включить `allowCredentials=true` — нельзя одновременно `allowedOriginPatterns("*")` (стандарт CORS такое запрещает).
