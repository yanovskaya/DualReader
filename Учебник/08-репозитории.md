# Глава 08. Репозитории

## Что такое репозиторий

**Репозиторий** — слой между бизнес-логикой и БД. Его задача — отвечать на вопросы вида «дай мне книгу с id=5», «сохрани этот абзац», «найди все параграфы с переводом».

В Spring Data JPA репозиторий — это **интерфейс** (не класс!), который наследуется от `JpaRepository`. Сам код реализации Spring пишет за вас в момент запуска.

## `BookRepository.java`

```java
package com.lingua.api.repository;

import com.lingua.api.model.Book;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.stereotype.Repository;

import java.util.List;

@Repository
public interface BookRepository extends JpaRepository<Book, Integer> {

    List<Book> findAllByOrderByCreatedAtAsc();

    @Query(value = "SELECT SUM(array_length(regexp_split_to_array(trim(original_text), '\\s+'), 1)) FROM paragraphs WHERE book_id = :bookId", nativeQuery = true)
    Long countWordsByBookId(Integer bookId);
}
```

Разберём.

### Аннотация `@Repository` и наследование

```java
@Repository
public interface BookRepository extends JpaRepository<Book, Integer> {
```

- `@Repository` — пометка для Spring: «это репозиторий, сделай из него бин». Технически Spring Data JPA увидит интерфейс и без неё, но явная аннотация — хорошая практика.
- `extends JpaRepository<Book, Integer>` — главная магия. `Book` — сущность, `Integer` — тип её первичного ключа.

**Бесплатно, наследуясь от `JpaRepository`,** мы получаем:
- `save(book)` — INSERT или UPDATE,
- `saveAll(books)` — то же, для списка (батч),
- `findById(id)` — `Optional<Book>`,
- `findAll()` — все записи,
- `existsById(id)` — `boolean`,
- `count()` — `long`,
- `deleteById(id)`,
- `delete(book)`,
- `deleteAll(books)`.

И ещё ~10 методов. Всё это уже работает без единой написанной строчки SQL.

### Производные методы (derived queries)

```java
List<Book> findAllByOrderByCreatedAtAsc();
```

Spring парсит **имя метода** и сам генерирует SQL. Грамматика:

```
find / count / exists / delete  +  By  +  <Поле>  +  <Условие>  +  OrderBy<Поле><Asc|Desc>
```

Пример:
- `findAllByOrderByCreatedAtAsc()` → `SELECT * FROM books ORDER BY created_at ASC`.

Из `ParagraphRepository`:
```java
long countByBookId(Integer bookId);
// → SELECT COUNT(*) FROM paragraphs WHERE book_id = ?

Page<Paragraph> findByBookIdOrderByPosition(Integer bookId, Pageable pageable);
// → SELECT * FROM paragraphs WHERE book_id = ? ORDER BY position [LIMIT/OFFSET из Pageable]

List<Paragraph> findByBookIdOrderByPosition(Integer bookId);
// → SELECT * FROM paragraphs WHERE book_id = ? ORDER BY position

List<Paragraph> findByBookIdAndIsTranslatedFalseOrderByPosition(Integer bookId);
// → SELECT * FROM paragraphs WHERE book_id = ? AND is_translated = false ORDER BY position
```

Ключевые слова, которые понимает Spring:
- `And`, `Or`
- `Equals`, `Not`
- `LessThan`, `GreaterThan`
- `Between`
- `Like`, `Containing`, `StartingWith`, `EndingWith`
- `IsNull`, `IsNotNull`
- `True`, `False`
- `OrderBy<Поле><Asc|Desc>`

Полная шпаргалка:
https://docs.spring.io/spring-data/jpa/docs/current/reference/html/#repository-query-keywords

### Когда производных методов мало — `@Query`

```java
@Query(value = "SELECT SUM(array_length(regexp_split_to_array(trim(original_text), '\\s+'), 1)) FROM paragraphs WHERE book_id = :bookId", nativeQuery = true)
Long countWordsByBookId(Integer bookId);
```

Если запрос сложный — пиши вручную через `@Query`. Два варианта:

**Native SQL** (`nativeQuery = true`):
- Пишешь чистый SQL для конкретной БД.
- Используешь имена таблиц и колонок.
- Можно использовать диалект-специфичные функции (`array_length`, `regexp_split_to_array` — это PostgreSQL).

**JPQL** (по умолчанию, без `nativeQuery`):
- Пишешь на «JPQL» — языке запросов JPA.
- Используешь имена **классов** и **полей**, не таблиц/колонок.
- Работает на любой БД.

Пример JPQL из `ParagraphRepository`:
```java
@Query("SELECT p FROM Paragraph p WHERE p.bookId = :bookId AND " +
       "(LOWER(p.originalText) LIKE LOWER(CONCAT('%', :q, '%')) OR " +
       "LOWER(p.translatedText) LIKE LOWER(CONCAT('%', :q, '%'))) " +
       "ORDER BY p.position")
List<Paragraph> searchByBookId(Integer bookId, String q, Pageable pageable);
```
Обрати внимание: `Paragraph p` — это имя сущности, а не таблицы. `p.bookId` — имя поля, а не колонки. JPQL знает про маппинг и сам всё переведёт в SQL.

`:bookId`, `:q` — **именованные параметры**. Имя соответствует имени аргумента метода.

## Параметры особого назначения

### `Pageable` — пагинация

```java
Page<Paragraph> findByBookIdOrderByPosition(Integer bookId, Pageable pageable);
```

`Pageable` — последний параметр любого метода. Spring сам добавит `LIMIT` и `OFFSET`.

Использование:
```java
PageRequest pr = PageRequest.of(0, 20);  // первая страница, 20 на страницу
Page<Paragraph> page = paragraphRepo.findByBookIdOrderByPosition(bookId, pr);

page.getContent();      // List<Paragraph>
page.getTotalElements(); // long — сколько ВСЕГО подходит
page.getTotalPages();    // int
```

`PageRequest.of(0, 20)` — нумерация страниц с **нуля**.

### `Sort` — сортировка
```java
Sort sort = Sort.by(Sort.Direction.DESC, "createdAt");
PageRequest.of(0, 20, sort);
```

## Что происходит при запуске

1. Spring видит `BookRepository extends JpaRepository`.
2. Spring Data **на лету** генерирует класс-реализацию (через прокси).
3. Этот класс зарегистрирован как бин с именем `bookRepository`.
4. Любой сервис, попросивший в конструкторе `BookRepository`, получит этот прокси.

Поэтому ты пишешь только интерфейс, а реализацию никогда не видишь.

## Транзакции

По умолчанию каждый вызов метода репозитория — отдельная транзакция. Если нужна общая транзакция (несколько `save` должны или все пройти, или все откатиться) — это делается на уровне сервиса через `@Transactional`. Об этом — следующая глава.

1. Чем интерфейс репозитория отличается от обычного класса?
2. Что мы получаем бесплатно, наследуясь от `JpaRepository<Book, Integer>`?
3. Что такое derived query? Что такое `@Query`?

## Мини-упражнение

Допустим, нам нужен метод «найти все книги, у которых статус перевода = 'failed'». Напиши его сигнатуру в `BookRepository`.

<details>
<summary>Подсказка / решение</summary>

```java
List<Book> findByTranslationStatus(String status);
```

Использование:
```java
List<Book> failed = bookRepo.findByTranslationStatus("failed");
```
</details>

Бонус: напиши то же самое, но через `@Query` на JPQL.

<details>
<summary>Решение</summary>

```java
@Query("SELECT b FROM Book b WHERE b.translationStatus = :status")
List<Book> findByStatus(String status);
```
</details>
