# Глава 09. Сервисы

> **Зачем эта глава:** научиться писать бизнес-логику в правильном слое.
> **Файл проекта:** `artifacts/api-server/src/main/java/com/lingua/api/service/BookService.java`

## Что такое сервис

Сервис — слой бизнес-логики. Он:
- комбинирует репозитории (например, чтобы создать книгу — сначала сохранить `Book`, потом сохранить `Paragraph`-ы),
- проверяет инварианты (например, «у книги должно быть >0 абзацев»),
- координирует сложные операции (с транзакциями, с асинхронностью),
- **не знает про HTTP**.

## Шапка `BookService`

```java
package com.lingua.api.service;

import ...

@Service
@RequiredArgsConstructor
public class BookService {

    private final BookRepository bookRepo;
    private final ParagraphRepository paragraphRepo;
```

### `@Service`

«Это бин-сервис». Технически почти то же, что `@Component`, но семантически: «здесь бизнес-логика».

### `@RequiredArgsConstructor` + `final`

Это **главный паттерн внедрения зависимостей**. Lombok сгенерирует конструктор:

```java
public BookService(BookRepository bookRepo, ParagraphRepository paragraphRepo) {
    this.bookRepo = bookRepo;
    this.paragraphRepo = paragraphRepo;
}
```

И Spring при создании бина передаст в этот конструктор уже созданные `BookRepository` и `ParagraphRepository`.

Почему `final`?
- `final` поле обязано быть инициализировано в конструкторе.
- Lombok генерирует конструктор именно для `final` полей.
- Гарантия неизменности: после конструктора ссылка не поменяется.

Это называется **constructor-based dependency injection**. Альтернативы (`@Autowired` на поле, setter injection) считаются устаревшими — пиши только так.

## Простые методы

```java
public List<Book> listBooks() {
    return bookRepo.findAllByOrderByCreatedAtAsc();
}

public Optional<Book> getBook(Integer id) {
    return bookRepo.findById(id);
}
```

Тонкие обёртки над репозиторием. Можно ли было звать репозиторий прямо из контроллера? Да. Но через сервис — лучше:
1. Если завтра логика усложнится (например, кэширование) — менять надо только сервис.
2. Контроллер не зависит от Spring Data напрямую.

## Создание книги — самый интересный метод

```java
@Transactional
public Book createBook(String title, String author, String language, String content) {
    List<String> rawParagraphs = Arrays.stream(content.split("\n\n+"))
            .map(String::trim)
            .filter(p -> p.length() > 10)
            .toList();

    Book book = new Book();
    book.setTitle(title);
    book.setAuthor(author);
    book.setLanguage(language != null ? language : "en");
    book.setTotalParagraphs(rawParagraphs.size());
    book.setTranslatedParagraphs(0);
    book.setTranslationStatus("pending");
    bookRepo.save(book);

    insertParagraphBatch(book.getId(), rawParagraphs);
    return book;
}
```

### `@Transactional`

**Самая важная аннотация в сервисах.** Метод выполняется в **одной транзакции БД**. Если в середине упадёт исключение — все изменения откатятся (rollback).

Без неё может произойти:
1. Сохранили `book` → коммит.
2. Начали сохранять параграфы → ошибка.
3. В БД осталась «осиротевшая» книга без параграфов.

С `@Transactional`:
1. Открыли транзакцию.
2. Сохранили `book`.
3. Сохранили параграфы. Ошибка → ROLLBACK всего.
4. Если без ошибок → COMMIT.

**Правило:** любой метод сервиса, который делает несколько записей в БД, должен быть `@Transactional`.

### Stream API

```java
List<String> rawParagraphs = Arrays.stream(content.split("\n\n+"))
        .map(String::trim)
        .filter(p -> p.length() > 10)
        .toList();
```

Это **функциональный стиль** Java 8+. Читается как пайплайн:
1. `content.split("\n\n+")` — разделить текст по пустым строкам, получить `String[]`.
2. `Arrays.stream(...)` — сделать из массива поток.
3. `.map(String::trim)` — для каждой строки убрать пробелы по краям.
4. `.filter(p -> p.length() > 10)` — оставить только длиннее 10 символов.
5. `.toList()` — собрать обратно в `List<String>`.

Аналог в Python: list comprehension. Аналог в JavaScript: `arr.map(...).filter(...)`.

`String::trim` — это **method reference** (ссылка на метод). Эквивалент `s -> s.trim()`. Чуть короче.

`p -> p.length() > 10` — это **лямбда-выражение**. Анонимная функция.

## Батч-вставка

```java
private void insertParagraphBatch(Integer bookId, List<String> texts) {
    List<Paragraph> batch = new ArrayList<>();
    for (int i = 0; i < texts.size(); i++) {
        Paragraph p = new Paragraph();
        p.setBookId(bookId);
        p.setPosition(i);
        p.setOriginalText(texts.get(i));
        p.setTranslated(false);
        batch.add(p);
        if (batch.size() == 200) {
            paragraphRepo.saveAll(batch);
            batch.clear();
        }
    }
    if (!batch.isEmpty()) {
        paragraphRepo.saveAll(batch);
    }
}
```

**Зачем батч?** У книги может быть 5000 абзацев. Делать 5000 отдельных `INSERT` — медленно (миллион round-trip к БД). Накапливаем по 200 и сохраняем разом — в **30 раз быстрее**.

`paragraphRepo.saveAll(...)` отправляет в БД пачку INSERT-ов одной транзакцией.

## `getParagraphs` — пагинация

```java
public Map<String, Object> getParagraphs(Integer bookId, int page, int pageSize) {
    long total = paragraphRepo.countByBookId(bookId);
    PageRequest pr = PageRequest.of(page - 1, pageSize);
    Page<Paragraph> pageResult = paragraphRepo.findByBookIdOrderByPosition(bookId, pr);

    List<Map<String, Object>> items = pageResult.getContent().stream()
            .map(this::paragraphToMap)
            .toList();

    Map<String, Object> result = new LinkedHashMap<>();
    result.put("paragraphs", items);
    result.put("total", total);
    result.put("page", page);
    result.put("pageSize", pageSize);
    result.put("totalPages", (int) Math.ceil((double) total / pageSize));
    return result;
}
```

Тонкости:
- В API страницы нумеруются с **1** (как привычно пользователю), а в `Pageable` — с **0**. Поэтому `page - 1`.
- `LinkedHashMap` сохраняет порядок ключей — JSON-ответ будет в том порядке, что мы написали.
- `(double) total / pageSize` — приведение к `double`, иначе будет целочисленное деление.

## Распознавание заголовков глав

```java
public static boolean isHeading(String text) {
    String t = text.trim();
    if (t.length() > 120) return false;
    if (Pattern.compile("^\\d+\\.\\s+\\S").matcher(t).find()) return true;
    if (Pattern.compile("^(chapter|part|section|prologue|epilogue|...)\\b", Pattern.CASE_INSENSITIVE).matcher(t).find()) return true;
    if (Pattern.compile("^[IVXLCDM]+\\.?\\s*$").matcher(t).matches()) return true;
    if (t.length() <= 60 && t.equals(t.toUpperCase()) && Pattern.compile("^[A-Z][A-Z\\s\\d'\"\\-]{2,}$").matcher(t).matches()) return true;
    return false;
}
```

Алгоритм проверяет по очереди:
1. Длиннее 120 символов — точно не заголовок.
2. Начинается с `1. Что-то` — заголовок.
3. Начинается со слов `Chapter`, `Part`, `Prologue` и т.д. — заголовок.
4. Это римская цифра отдельной строкой (`II`, `IV`).
5. Короткая строка ВСЯ В ВЕРХНЕМ РЕГИСТРЕ — заголовок.

`Pattern.compile(...).matcher(t).find()` — стандартный способ применить регулярное выражение в Java.
- `find()` — найти где-то в строке.
- `matches()` — вся строка должна соответствовать.

## Мини-упражнение

Добавь в `BookService` метод `getBookOrThrow(Integer id)`, который возвращает `Book` или бросает `NoSuchElementException`, если книги нет.

<details>
<summary>Решение</summary>

```java
public Book getBookOrThrow(Integer id) {
    return bookRepo.findById(id)
            .orElseThrow(() -> new NoSuchElementException("Book not found: " + id));
}
```

`Optional.orElseThrow(supplier)` — если `Optional` пустой, бросает то, что вернул `supplier`.
