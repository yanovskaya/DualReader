# Шаг 03. Первый эндпоинт `/healthz`

🎯 **Цель:** запустить сервер и получить ответ от `GET /healthz`.

📁 **Файлы шага:**
- `src/main/java/com/lingua/api/LinguaApiApplication.java` — главный класс
- `src/main/java/com/lingua/api/controller/HealthController.java` — наш первый эндпоинт
- `src/main/resources/application.properties` — настройки

## 1. Главный класс

В Java приложение **обязано** иметь точку входа — статический метод `main`. Создай файл:

**`src/main/java/com/lingua/api/LinguaApiApplication.java`**

```java
package com.lingua.api;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class LinguaApiApplication {
    public static void main(String[] args) {
        SpringApplication.run(LinguaApiApplication.class, args);
    }
}
```

🧠 **Разбор:**

- `package com.lingua.api;` — путь к файлу должен совпадать (`com/lingua/api/`). Это требование Java.
- `@SpringBootApplication` — самая важная аннотация. Она объединяет три:
  - `@Configuration` — «класс умеет настраивать бины»,
  - `@EnableAutoConfiguration` — «Spring Boot, посмотри какие библиотеки подключены и настрой их сам» (нашёл `spring-boot-starter-web` → запустит Tomcat на 8080),
  - `@ComponentScan` — «просканируй текущий пакет (`com.lingua.api`) и все подпапки в поисках бинов».
- `SpringApplication.run(...)` — гигантская функция, которая запускает Tomcat, создаёт контейнер бинов и возвращает только когда сервер реально слушает порт.

> 💡 **Почему главный класс лежит в `com/lingua/api/`, а не глубже?** Потому что `@ComponentScan` сканирует свой пакет и подпакеты. Все остальные классы (`controller/`, `service/`...) будут в подпапках — Spring их найдёт.

## 2. Настройки

Создай файл **`src/main/resources/application.properties`**:

```properties
server.port=${PORT:8080}
```

🧠 `${PORT:8080}` — «возьми переменную окружения `PORT`, а если её нет — 8080». В Replit переменная `PORT` обычно установлена; локально будет 8080.

## 3. Первый эндпоинт

Создай папку `controller/`:

```bash
mkdir -p src/main/java/com/lingua/api/controller
```

И файл **`src/main/java/com/lingua/api/controller/HealthController.java`**:

```java
package com.lingua.api.controller;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.Map;

@RestController
public class HealthController {

    @GetMapping("/healthz")
    public ResponseEntity<Map<String, String>> health() {
        return ResponseEntity.ok(Map.of("status", "ok"));
    }
}
```

🧠 **Разбор:**

- `@RestController` — «это HTTP-контроллер, каждый метод возвращает JSON». При запуске Spring найдёт класс благодаря `@ComponentScan` и зарегистрирует.
- `@GetMapping("/healthz")` — «обработай `GET /healthz`».
- `ResponseEntity.ok(...)` — оборачивает ответ с кодом 200.
- `Map.of("status", "ok")` — Jackson (входит в starter-web) автоматически сериализует это в `{"status":"ok"}`.

## 4. Запускаем

```bash
mvn spring-boot:run
```

Через 5-15 секунд увидишь знаменитый ASCII-баннер Spring и в конце:

```
Tomcat started on port 8080 (http) with context path ''
Started LinguaApiApplication in 2.345 seconds
```

Сервер работает!

## ✅ Проверка

В **другом терминале** (этот занят сервером):

```bash
curl http://localhost:8080/healthz
```

Ожидаемый ответ:
```json
{"status":"ok"}
```

🎉 У тебя работает Java-веб-сервер!

Чтобы остановить — нажми Ctrl+C в терминале с `mvn spring-boot:run`.
