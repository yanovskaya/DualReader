# Глава 01. Что такое Spring Boot

> **Зачем эта глава:** разобраться с базовыми концепциями, без которых дальнейший код будет выглядеть как магия.

## Краткий контекст

**Java** — язык программирования. Сам по себе он умеет немного: вывести «Hello World», посчитать что-то, открыть файл. Чтобы написать веб-сервер на голой Java, нужно вручную:
- открыть TCP-сокет,
- разобрать HTTP-запрос,
- сформировать ответ,
- подключиться к БД,
- сериализовать объект в JSON,
- ...и так ещё страниц на двести.

Никто так не делает. Все используют **фреймворки** — готовый «скелет» приложения, который уже умеет всё это.

## Spring и Spring Boot

**Spring** — самый популярный Java-фреймворк. Он умеет всё: веб, БД, безопасность, очереди сообщений и т.д.

**Spring Boot** — обёртка вокруг Spring, которая всё это **автоматически настраивает**. Вы пишете три строчки кода — у вас уже работает HTTP-сервер.

Сравни:
- Spring без Boot: написать XML-конфиги на 200 строк, чтобы запустить пустой сервер.
- Spring Boot: написать `main` метод и одну аннотацию — и сервер работает.

Поэтому **в новых проектах всегда берут Spring Boot.**

## Главная идея — Inversion of Control (IoC)

Это сложно звучит, но на пальцах объясняется так.

**Как обычно (без Spring):**
```java
public class App {
    public static void main(String[] args) {
        Database db = new Database("postgres://...");
        BookRepository repo = new BookRepository(db);
        BookService service = new BookService(repo);
        BookController controller = new BookController(service);
        // и т.д.
    }
}
```
Программист сам создаёт все объекты и связывает их.

**С Spring:**
```java
@Service
public class BookService {
    private final BookRepository repo;   // ← Spring сам сюда положит
}
```
Программист только пишет классы и помечает их аннотациями. **Spring сам** находит классы, создаёт их, подсовывает зависимости.

«Inversion of Control» = «инверсия управления»: раньше мы управляли созданием объектов, теперь Spring управляет за нас.

Конкретный механизм, как Spring подсовывает зависимости, называется **Dependency Injection (DI)** — внедрение зависимостей.

## Бины (beans)

**Бин** — это любой объект, которым управляет Spring.

При запуске Spring:
1. Сканирует все ваши Java-классы.
2. Находит классы с аннотациями `@Service`, `@Repository`, `@Controller`, `@Component`, `@Configuration`.
3. Создаёт по одному экземпляру каждого (по умолчанию — singleton).
4. Складывает их в **ApplicationContext** — внутреннее хранилище бинов.
5. Когда какому-то бину в конструкторе нужен другой бин — Spring его туда подсовывает.

То есть весь ваш проект превращается в **граф связанных бинов**, и Spring сам строит этот граф.

## Аннотации — это пометки для Spring

Аннотация в Java — это `@Что-то` над классом или методом. Сама по себе она ничего не делает: это просто пометка-метаданные. Spring при старте читает эти пометки и понимает, что делать.

Главные «семейства» аннотаций, которые встретятся:
- `@Service` / `@Repository` / `@Controller` / `@Component` — «сделай этот класс бином».
- `@Autowired` / `@RequiredArgsConstructor` — «подставь сюда зависимость».
- `@GetMapping` / `@PostMapping` — «обработай такой HTTP-запрос».
- `@Entity` / `@Column` — «эта модель — таблица в БД».
- `@Async` / `@Transactional` — «выполни этот метод в фоне / в транзакции».

В каждой следующей главе мы будем встречать новые аннотации — и каждый раз я буду объяснять, что они делают.

## Мини-упражнение

Открой папку `artifacts/api-server/src/main/java/com/lingua/api/` и просто посмотри на структуру. Не вчитываясь в код — найди:
- хотя бы один класс с `@Service`,
- хотя бы один класс с `@RestController`,
- хотя бы один класс с `@Configuration`.

Это — **бины**. Spring создаст их при запуске и свяжет.
