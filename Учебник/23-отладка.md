# Шаг 23. Отладка: как не сойти с ума

🎯 **Цель:** научиться читать ошибки Spring, видеть SQL-запросы и быстро находить причину, когда «ничего не работает».

## 1. Включи `show-sql`

Самое полезное, что ты можешь сделать прямо сейчас. Открой `application.properties` и **на время отладки** добавь:

```properties
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
logging.level.org.hibernate.orm.jdbc.bind=trace
```

Теперь в логах ты увидишь:

```
Hibernate:
    select
        b1_0.id, b1_0.title, b1_0.author
    from
        books b1_0
    where
        b1_0.id=?
binding parameter (1:INTEGER) <- [42]
```

Это **золото**. Когда «JPA-запрос работает не так, как ожидалось», SQL покажет правду.

⚠️ В продакшене эти настройки **выключи** — они забивают логи.

## 2. Как читать stacktrace Spring

Stacktrace в Spring длинный и страшный. Главное правило: **читай снизу вверх до первого `Caused by:`**, потом ищи **первую строку с твоим пакетом** (`com.lingua.api.*`).

Пример:
```
org.springframework.dao.DataIntegrityViolationException: ...
    at org.springframework.orm.jpa.vendor.HibernateJpaDialect.convertHibernateAccessException(...)
    at org.springframework.orm.jpa.vendor.HibernateJpaDialect.translateExceptionIfPossible(...)
    ... 50 more строк фреймворка ...
Caused by: org.hibernate.exception.ConstraintViolationException: could not execute statement
    ... ещё 30 строк ...
Caused by: org.postgresql.util.PSQLException: ERROR: null value in column "title" violates not-null constraint
    at org.postgresql.core.v3.QueryExecutorImpl.receiveErrorResponse(...)
    at com.lingua.api.service.BookService.createBook(BookService.java:42)  ← ВОТ ОНО
```

- Самое нижнее `Caused by:` — **настоящая причина**.
- Строка с `com.lingua.api.*` — где **в твоём коде** это произошло.

## 3. Топ-7 типичных ошибок

### 3.1. `Port 8080 was already in use`

```
Web server failed to start. Port 8080 was already in use.
```

Где-то висит старый процесс. Найди и убей:
```bash
lsof -ti:8080 | xargs kill -9
```

Или поменяй порт в `application.properties`.

### 3.2. `Field xxx in YyyController required a bean of type 'Zzz' that could not be found`

Spring не нашёл, кого положить в зависимость. Причины:
- Забыла `@Service`/`@Repository`/`@Component` на классе.
- Класс лежит **вне** пакета `com.lingua.api` (Spring сканирует только подпакеты главного класса).
- Опечатка в имени интерфейса.

### 3.3. `Table "BOOKS" not found` или `relation "books" does not exist`

База пустая или ты подключилась не к той БД. Проверь:
```bash
psql $DATABASE_URL -c '\dt'
```

Если таблиц нет — выполни SQL-схему из [Шага 04](04-база-данных.md).

### 3.4. `LazyInitializationException`

```
failed to lazily initialize a collection of role: ... no Session
```

Ты обращаешься к связанной коллекции **вне** транзакции. Решения:
- Помечай метод сервиса `@Transactional`.
- Или используй `@Query` с `JOIN FETCH`.
- Или (как у нас) — не используй `@OneToMany`, а делай отдельные запросы.

### 3.5. `Could not commit JPA transaction` / Constraint violation

Смотри последнее `Caused by:` — там будет SQL-ошибка PostgreSQL: `null value`, `duplicate key`, `foreign key`. Чаще всего:
- Не указала обязательное поле.
- Дублируешь уникальный ключ.
- Удаляешь книгу, на которую ссылаются параграфы (а у нас `ON DELETE CASCADE`, поэтому такой ошибки быть не должно).

### 3.6. `JSON parse error: Cannot construct instance of...`

Клиент прислал JSON, который Jackson не смог распарсить в твой DTO. Причины:
- Не хватает no-args конструктора (нужен `@NoArgsConstructor` от Lombok).
- Имя поля в JSON не совпадает с полем класса.
- Тип не совпадает (например, прислали строку, а ждём число).

### 3.7. `Whitelabel Error Page` 404

Ты обратилась на эндпоинт, которого нет. Проверь:
- Метод (`GET` vs `POST`).
- Путь — не забыла ли префикс `/api`?
- Порт.

## 4. Уровни логов

```properties
# Меняй уровни прицельно, без фанатизма
logging.level.com.lingua.api=DEBUG
logging.level.org.springframework.web=DEBUG
logging.level.org.springframework.transaction=DEBUG
logging.level.org.hibernate.SQL=DEBUG
```

Уровни от шумного к тихому: `TRACE → DEBUG → INFO → WARN → ERROR`.

## 5. Логи в коде

Внутри сервиса:

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

private static final Logger log = LoggerFactory.getLogger(BookService.class);

public Book create(...) {
    log.info("Creating book: {}", title);
    log.debug("Full payload: {}", payload);
    try {
        // ...
    } catch (Exception e) {
        log.error("Failed to create book", e);
        throw e;
    }
}
```

Или через Lombok:
```java
@Slf4j
public class BookService { ... }
```

⚠️ **Никогда** не используй `System.out.println` в продакшен-коде — нет уровней, нет timestamp, нельзя выключить.

## 6. Отладка через curl с подробностями

```bash
# -v показывает заголовки запроса/ответа
curl -v http://localhost:8080/books

# -i показывает заголовки ответа
curl -i http://localhost:8080/books

# Красивый JSON
curl http://localhost:8080/books | jq

# Отправить JSON и увидеть заголовки
curl -i -X POST http://localhost:8080/books \
  -H 'Content-Type: application/json' \
  -d '{"title":"Test","author":"Me","sourceLang":"en","targetLang":"ru","content":"Hello"}'
```

## 7. Чек-лист «приложение не стартует»

1. Прочитай **последнее** `Caused by:` в логах.
2. Проверь, что `DATABASE_URL` установлена: `echo $DATABASE_URL`.
3. Проверь, что Postgres жив: `psql $DATABASE_URL -c 'SELECT 1'`.
4. Проверь, что нужный порт свободен: `lsof -i:8080`.
5. Сделай `mvn clean` и попробуй снова — иногда помогает.

## 8. Чек-лист «эндпоинт возвращает не то»

1. Включи `show-sql` — посмотри, что улетело в БД.
2. Сделай тот же запрос **прямо в `psql`** — данные правильные?
3. Поставь `log.info("got: {}", value)` в сервисе — что пришло?
4. Проверь, что Jackson сериализует поля как ты ждёшь (имена полей, `@JsonProperty`).

## ✅ Проверка

Сделай специально ошибку, чтобы попрактиковаться:

1. Останови сервер. В `BookController` удали `@RequestMapping` или `@RestController` и попробуй стартануть. Прочитай ошибку.
2. Верни. В `application.properties` укажи неправильный URL базы. Стартуй. Прочитай ошибку.
3. Верни. В `Book.java` убери `@NoArgsConstructor`. Стартуй. Что произошло?

После каждого опыта — **верни всё как было**.
