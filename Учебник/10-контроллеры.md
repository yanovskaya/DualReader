## Самый простой пример — `HealthController`

```java
@RestController
public class HealthController {

    @GetMapping("/healthz")
    public ResponseEntity<Map<String, String>> health() {
        return ResponseEntity.ok(Map.of("status", "ok"));
    }
}
```

5 строк. Объясняю каждый кусочек.

### `@RestController`

«Это контроллер, и каждый метод возвращает не имя HTML-шаблона, а данные напрямую — JSON».

Это сокращение от двух аннотаций: `@Controller` + `@ResponseBody`.

### `@GetMapping("/healthz")`

«Метод обрабатывает HTTP `GET /healthz`».

Аналоги:
- `@PostMapping("/path")` — POST.
- `@PutMapping("/path")` — PUT.
- `@DeleteMapping("/path")` — DELETE.
- `@PatchMapping("/path")` — PATCH.

> Помни про префикс `/api` из `application.properties` (`server.servlet.context-path=/api`). Полный путь будет `/api/healthz`.

### `ResponseEntity`

Обёртка над ответом. Позволяет задать:
- тело,
- HTTP-статус (200, 404, 500…),
- заголовки.

Сокращения:
- `ResponseEntity.ok(body)` → 200.
- `ResponseEntity.notFound().build()` → 404.
- `ResponseEntity.badRequest().body(...)` → 400.
- `ResponseEntity.noContent().build()` → 204.
- `ResponseEntity.status(201).body(...)` → произвольный код.

### `Map.of(...)` и Jackson

```java
Map.of("status", "ok")
```
`Map.of` создаёт неизменяемую `Map`. Jackson (входит в Spring Boot Web) автоматически сериализует её в JSON: `{"status":"ok"}`.

## Чтение path-параметра

```java
@GetMapping("/books/{id}")
public ResponseEntity<?> getBook(@PathVariable Integer id) {
    return bookService.getBook(id)
            .map(b -> ResponseEntity.ok(bookToMap(b)))
            .orElse(ResponseEntity.notFound().build());
}
```

- `{id}` в пути — placeholder.
- `@PathVariable Integer id` — Spring возьмёт строку из URL и **сам распарсит** в `Integer`. Если не получится — вернёт 400.

Если имя параметра в пути и в Java отличается, нужно указать явно:
```java
@GetMapping("/books/{bookId}")
public ResponseEntity<?> getBook(@PathVariable("bookId") Integer id) { ... }
```

## Чтение query-параметров

```java
@GetMapping("/books/{id}/paragraphs")
public ResponseEntity<?> getParagraphs(
        @PathVariable Integer id,
        @RequestParam(defaultValue = "1") int page,
        @RequestParam(defaultValue = "20") int pageSize) {
```

Запрос: `GET /api/books/5/paragraphs?page=2&pageSize=50`.

- `@RequestParam(defaultValue = "1") int page` — берёт `?page=...`. Если не передан → `1`.
- `required = false` — параметр опционален, может быть `null`.

Пример с опциональным параметром:
```java
@RequestParam(required = false) String q
```

## Чтение JSON-тела

```java
@PostMapping("/books")
public ResponseEntity<?> createBook(@RequestBody Map<String, Object> body) {
    String title = (String) body.get("title");
    String author = (String) body.get("author");
    ...
}
```

`@RequestBody` — Jackson распарсит JSON-тело в указанный тип.

Тут мы парсим в **универсальную `Map`** — это удобно, когда полей мало и не хочется создавать класс. Но **рекомендуется** делать DTO-класс:

```java
public record CreateBookRequest(String title, String author, String language, String content) {}

@PostMapping("/books")
public ResponseEntity<?> createBook(@RequestBody CreateBookRequest req) {
    bookService.createBook(req.title(), req.author(), req.language(), req.content());
}
```

`record` — короткий способ объявить класс-носитель данных в Java 14+.

## Валидация и ответы об ошибках

```java
if (title == null || title.isBlank()) {
    return ResponseEntity.badRequest().body(Map.of("error", "title is required"));
}
```

Простая ручная валидация. Возвращаем 400 + JSON `{"error": "..."}`.

Альтернатива — **Bean Validation** (`@NotBlank`, `@Min` и т.д.), но это отдельная большая тема.

## `Optional` + функциональный стиль

```java
return bookService.getBook(id)
        .map(b -> ResponseEntity.ok(bookToMap(b)))
        .orElse(ResponseEntity.notFound().build());
```

Чище, чем if/else:
- `getBook(id)` возвращает `Optional<Book>`.
- `.map(...)` — если внутри что-то есть, преобразовать.
- `.orElse(...)` — если `Optional` пустой, использовать это.

Эквивалент:
```java
Optional<Book> opt = bookService.getBook(id);
if (opt.isPresent()) {
    return ResponseEntity.ok(bookToMap(opt.get()));
} else {
    return ResponseEntity.notFound().build();
}
```

## Группировка эндпоинтов: `@RequestMapping` на классе

```java
@RestController
@RequestMapping("/dictionary")
public class DictionaryController {

    @GetMapping("/lookup")  // = /dictionary/lookup
    public ... lookup(...) { ... }

    @GetMapping("/recent")  // = /dictionary/recent
    public ... recent() { ... }
}
```

`@RequestMapping("/dictionary")` на классе — общий префикс. Внутри методов пишешь только хвост.

## Преобразование сущности в JSON-ответ

В нашем контроллере есть метод-помощник:

```java
private Map<String, Object> bookToMap(Book b) {
    Map<String, Object> m = new LinkedHashMap<>();
    m.put("id", b.getId());
    m.put("title", b.getTitle());
    m.put("author", b.getAuthor());
    ...
    return m;
}
```

Зачем не отдавать `Book` напрямую? Чтобы:
1. Контролировать формат JSON (например, `createdAt` как строка).
2. Не отдавать поля, которые не нужны клиенту.
3. Не зависеть от изменений в модели — поля в API стабильны.

В больших проектах для этого делают **DTO** (Data Transfer Object) — отдельные классы под каждое API-представление.

## Возврат разных HTTP-статусов

| Что | Метод | Когда |
|---|---|---|
| 200 OK | `ResponseEntity.ok(body)` | Всё хорошо, есть тело |
| 201 Created | `ResponseEntity.status(201).body(body)` | Ресурс создан |
| 204 No Content | `ResponseEntity.noContent().build()` | Удаление успешно, тела нет |
| 400 Bad Request | `ResponseEntity.badRequest().body(...)` | Невалидный запрос |
| 404 Not Found | `ResponseEntity.notFound().build()` | Не нашли |
| 500 Internal Server Error | `ResponseEntity.internalServerError().body(...)` | Что-то упало |

## Полный мини-пример — POST с валидацией

```java
@PostMapping("/books")
public ResponseEntity<?> createBook(@RequestBody Map<String, Object> body) {
    String title = (String) body.get("title");
    String content = (String) body.get("content");

    if (title == null || title.isBlank()) {
        return ResponseEntity.badRequest().body(Map.of("error", "title is required"));
    }
    if (content == null || content.isBlank()) {
        return ResponseEntity.badRequest().body(Map.of("error", "content is required"));
    }

    Book book = bookService.createBook(title, null, null, content);
    return ResponseEntity.status(201).body(bookToMap(book));
}
```

Этот шаблон — **70% работы любого REST-контроллера**:
1. Принять параметры.
2. Провалидировать.
3. Если плохо — 400.
4. Позвать сервис.
5. Сформировать ответ.

## Мини-упражнение

Напиши эндпоинт `GET /api/echo?text=...`, который возвращает JSON `{"echo": "<полученный текст>"}`. Если параметра нет — 400.

<details>
<summary>Решение</summary>

```java
@RestController
public class EchoController {

    @GetMapping("/echo")
    public ResponseEntity<?> echo(@RequestParam(required = false) String text) {
        if (text == null || text.isBlank()) {
            return ResponseEntity.badRequest().body(Map.of("error", "text is required"));
        }
        return ResponseEntity.ok(Map.of("echo", text));
    }
}
```

Положи в `controller/EchoController.java`, перезапусти сервер, проверь:
```
curl 'localhost:80/api/echo?text=hello'
→ {"echo":"hello"}
```
</details>
