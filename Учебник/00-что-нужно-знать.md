# Шаг 00. Что нужно знать заранее

🎯 **Цель:** убедиться, что ты понимаешь базовый Java-синтаксис и термины, которые встретятся дальше. Это **не курс по Java** — только то, без чего следующие шаги будут казаться магией.

Если ты пришла из JavaScript/Python — читай внимательно, отличий много. Если уже писала на Java — пробеги глазами и переходи к [Шагу 01](01-установка.md).

## 1. Файл = класс

В Java **один публичный класс на файл**, и имя файла должно совпадать с именем класса.

```java
// Файл: Book.java
public class Book {
    // ...
}
```

Файл `Book.java` обязан содержать `public class Book`. Никаких функций «в воздухе», как в JS, — всё живёт внутри класса.

## 2. Пакеты = папки

```java
package com.lingua.api.model;
```

Эта строка означает: «класс лежит в папке `com/lingua/api/model/`». Структура папок и пакетов **должна совпадать**, иначе компилятор ругнётся.

Импорт из другого пакета:
```java
import com.lingua.api.model.Book;
```

## 3. Типы обязательны

```java
String name = "Война и мир";
int year = 1869;
boolean isPublished = true;
List<String> chapters = new ArrayList<>();
```

В отличие от JS, тип переменной фиксирован. Нельзя `name = 42` после `String name = "..."`.

Можно написать `var name = "Война и мир";` — компилятор сам выведет тип, но переменная всё равно будет `String` навсегда.

## 4. Классы и объекты

```java
public class Book {
    private String title;          // поле
    private int year;

    public Book(String title) {    // конструктор
        this.title = title;
    }

    public String getTitle() {     // метод (геттер)
        return title;
    }
}
```

Создаём объект:
```java
Book b = new Book("Война и мир");
String t = b.getTitle();
```

`new` обязателен — без него ничего не создаётся.

## 5. `private` / `public` (модификаторы доступа)

- `private` — доступно только внутри своего класса.
- `public` — доступно отовсюду.
- Без слова — package-private (виден только внутри своего пакета).

Поля обычно `private`, методы — `public`. К private-полям обращаются через геттеры/сеттеры.

## 6. Дженерики `<T>`

```java
List<String> names = new ArrayList<>();
Map<String, Integer> counts = new HashMap<>();
```

`List<String>` = «список строк». В отличие от JS-массивов, в `List<String>` можно положить **только** строки.

## 7. Интерфейсы

```java
public interface BookRepository {
    Book findById(Integer id);
}
```

Интерфейс — это контракт: «у того, кто реализует меня, должен быть метод `findById`». Реализация:
```java
public class BookRepositoryImpl implements BookRepository {
    public Book findById(Integer id) { ... }
}
```

В Spring мы часто пишем **только интерфейс** — реализацию делает фреймворк за нас (магия Spring Data JPA).

## 8. Аннотации `@Что-то`

```java
@RestController
@RequestMapping("/books")
public class BookController { }
```

Аннотация — это **метка для фреймворка**. Сама по себе ничего не делает; её читает Spring при запуске и принимает решения («ага, это контроллер, обрабатывает HTTP»).

В JS-мире аналог — декораторы (`@Component` в Angular). В Python — декораторы (`@app.route`).

## 9. `void`, `return`, типы возвращаемых значений

```java
public String greet(String name) {
    return "Привет, " + name;
}

public void log(String msg) {
    System.out.println(msg);
}
```

`void` = «ничего не возвращаю». В сигнатуре метода тип возвращаемого значения **обязателен**.

## 10. `null`, `Optional`

`null` существует и опасен (`NullPointerException` — самая частая ошибка в Java). Современный стиль — оборачивать «может-не-быть» в `Optional<T>`:

```java
Optional<Book> book = repository.findById(1);
if (book.isPresent()) {
    System.out.println(book.get().getTitle());
}
```

## 11. Исключения

```java
try {
    riskyOperation();
} catch (IOException e) {
    System.err.println("Ошибка: " + e.getMessage());
}
```

Некоторые ошибки (`checked`) нужно обрабатывать обязательно — иначе компилятор не даст собрать. Остальные (`RuntimeException`) — на твоё усмотрение.

## 12. Lambda и стримы (короткое введение)

```java
List<String> names = books.stream()
    .filter(b -> b.getYear() > 2000)
    .map(b -> b.getTitle())
    .toList();
```

`b -> b.getTitle()` — лямбда (анонимная функция). `.stream()` превращает коллекцию в «поток», по которому можно цепочкой вызывать `filter/map/reduce`.

Похоже на `array.filter().map()` в JS, но синтаксис другой.

## 13. Maven и `pom.xml`

Maven — это `npm` для Java. Файл `pom.xml` = `package.json`. Команды:

| npm | Maven |
|---|---|
| `npm install` | `mvn install` |
| `npm run start` | `mvn spring-boot:run` |
| `npm test` | `mvn test` |
| `npm run build` | `mvn package` |

## 14. Главное про Spring Boot одним абзацем

**Spring Boot** запускает встроенный веб-сервер (Tomcat) и сам сканирует все классы с аннотациями (`@Component`, `@Service`, `@Repository`, `@RestController`). Найдя их, он создаёт по одному объекту каждого класса (это называется **bean**) и держит у себя в **контейнере**. Когда одному бину нужен другой — Spring сам подставляет его в конструктор. Это и есть **Dependency Injection (DI)**.

Когда придёт HTTP-запрос — Spring найдёт подходящий `@RestController` и вызовет его метод.
