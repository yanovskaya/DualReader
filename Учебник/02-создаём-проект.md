# Шаг 02. Создаём пустой проект

🎯 **Цель:** есть структура папок Maven-проекта и `pom.xml`, по которому Maven скачает зависимости.

📁 **Файлы шага:**
- `pom.xml`

## Структура папок

В корне проекта (`~/my-lingua/`) создай такую структуру:

```
my-lingua/
├── pom.xml
└── src/
    └── main/
        ├── java/
        │   └── com/
        │       └── lingua/
        │           └── api/
        │               └── (пока пусто)
        └── resources/
            └── (пока пусто)
```

Команды для создания папок:

```bash
mkdir -p src/main/java/com/lingua/api
mkdir -p src/main/resources
```

🧠 **Зачем такая глубокая структура?** В Java каждый класс лежит в **пакете** (package). Имя пакета — обратное доменное имя (`com.lingua.api`). Папки на диске **обязаны** один в один повторять имя пакета. Это требование самого языка.

## Создаём `pom.xml`

В **корне проекта** создай файл `pom.xml` с таким содержимым:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>3.2.5</version>
        <relativePath/>
    </parent>

    <groupId>com.lingua</groupId>
    <artifactId>lingua-api-server</artifactId>
    <version>0.0.1-SNAPSHOT</version>
    <name>Lingua API Server</name>

    <properties>
        <java.version>17</java.version>
    </properties>

    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>
</project>
```

🧠 **Что мы здесь объявили:**

| Секция | Что значит |
|---|---|
| `<parent>` | Наследуем готовые настройки от родительского POM Spring Boot 3.2.5. Он подскажет Maven версии всех библиотек. |
| `<groupId>` + `<artifactId>` + `<version>` | «Координаты» нашего проекта (как обратный домен + имя). |
| `<java.version>17</java.version>` | Используем Java 17. |
| `spring-boot-starter-web` | Это **starter** — пакет, который тянет за собой всё для веб-сервера: Tomcat, Spring MVC, Jackson (JSON). |
| `<build>` + `spring-boot-maven-plugin` | Плагин, чтобы запускать приложение командой `mvn spring-boot:run`. |

> Позже мы будем добавлять в `<dependencies>` новые библиотеки по мере необходимости (БД, Lombok и т.д.). Сейчас только web.

## ✅ Проверка

Запусти из корня проекта:

```bash
mvn compile
```

Maven должен **скачать кучу библиотек** (это нормально — первый раз это занимает 1-2 минуты), а в конце вывести:

```
[INFO] BUILD SUCCESS
```

Появится папка `target/` (Maven кладёт туда скомпилированные `.class` файлы). Не трогай её, она автогенерируется.

Если получаешь `BUILD FAILURE` — внимательно прочитай ошибку. Чаще всего это:
- неправильный путь к `pom.xml` (запускай из корня!),
- опечатка в XML,
- отсутствие интернета (Maven скачивает зависимости).
