# Глава 05. Точка входа

> **Зачем эта глава:** понять, что именно запускает Spring Boot и как.
> **Файл проекта:** `artifacts/api-server/src/main/java/com/lingua/api/LinguaApiApplication.java`

## Полный код

Это весь файл целиком — 13 строк:

```java
package com.lingua.api;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.scheduling.annotation.EnableAsync;

@SpringBootApplication
@EnableAsync
public class LinguaApiApplication {
    public static void main(String[] args) {
        SpringApplication.run(LinguaApiApplication.class, args);
    }
}
```

Эти 13 строк запускают веб-сервер, подключают БД, поднимают весь Spring-контекст. Разберём построчно.

## Строка 1: package

```java
package com.lingua.api;
```

Объявление пакета. Файл лежит в папке `com/lingua/api/` — имя пакета должно совпадать. Java-компилятор не запустит файл, если эти два не совпадают.

## Строки 3–5: импорты

```java
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.scheduling.annotation.EnableAsync;
```

В Java каждый класс из другого пакета нужно явно импортировать. Здесь мы импортируем:
- `SpringApplication` — класс, у которого есть статический метод `run(...)`.
- Аннотации `@SpringBootApplication` и `@EnableAsync`.

## Аннотация `@SpringBootApplication`

```java
@SpringBootApplication
```

Это **самая важная аннотация** во всём приложении. Она объединяет три аннотации сразу:

### 1. `@Configuration`
Помечает класс как «источник конфигурации». То есть в этом классе можно объявлять `@Bean`-методы. Мы пока этого не делаем, но возможность есть.

### 2. `@EnableAutoConfiguration`
Главная магия Spring Boot. Spring сканирует classpath (все подключённые библиотеки) и **автоматически настраивает** всё, что найдёт:
- Нашёл `spring-boot-starter-web` → запустил Tomcat на порту 8080.
- Нашёл `spring-boot-starter-data-jpa` + PostgreSQL-драйвер → настроил JPA.
- Нашёл `application.properties` → загрузил из него настройки.
- Нашёл `spring-boot-starter-actuator` → поднял `/actuator/health`.

Без этой аннотации пришлось бы конфигурировать всё руками.

### 3. `@ComponentScan`
«Просканируй текущий пакет (`com.lingua.api`) и все подпакеты в поисках классов с аннотациями `@Component`, `@Service`, `@Repository`, `@Controller`, `@Configuration`. Все найденные классы — сделай бинами.»

> **Важно:** сканирование начинается с пакета, в котором лежит главный класс. Поэтому главный класс кладут в **корень** пакета приложения (`com.lingua.api`), а все остальные — в подпакеты (`com.lingua.api.controller`, `com.lingua.api.service` и т.д.). Если положить главный класс глубже — Spring не найдёт «соседей» сверху.

## Аннотация `@EnableAsync`

```java
@EnableAsync
```

Включает поддержку `@Async`. Без неё аннотация `@Async` на методах сервисов **тихо игнорируется** — метод выполнится синхронно, и ты будешь часами думать, почему перевод блокирует HTTP-запрос.

Очень частая ошибка новичков: добавили `@Async`, но не написали `@EnableAsync` где-то в конфигурации.

## Метод `main`

```java
public class LinguaApiApplication {
    public static void main(String[] args) {
        SpringApplication.run(LinguaApiApplication.class, args);
    }
}
```

Любая Java-программа стартует с метода `public static void main(String[] args)`. Это договор языка.

`SpringApplication.run(...)` делает огромную работу:
1. Создаёт `ApplicationContext` — контейнер бинов.
2. Загружает `application.properties`.
3. Сканирует пакеты (благодаря `@ComponentScan`).
4. Создаёт все бины и связывает их (Dependency Injection).
5. Запускает встроенный Tomcat.
6. Выводит знаменитый ASCII-баннер Spring в консоль.
7. Возвращает управление, но процесс продолжает работать (Tomcat держит главный поток).

С этого момента сервер слушает HTTP-запросы.

## Мини-упражнение

1. Открой `LinguaApiApplication.java` в редакторе.
2. Закомментируй `@EnableAsync`. Перезапусти workflow. Внешне всё работает? Да. Но если нажать «Перевести книгу» — увидишь, что HTTP-запрос будет висеть, пока перевод не закончится. Это потому что `@Async` без `@EnableAsync` не работает.
3. Раскомментируй обратно.
