# Глава 14. Добавляем свой эндпоинт с нуля

> **Зачем эта глава:** соединить всё, что узнали, на практическом примере.

В этой главе мы добавим новый эндпоинт **`GET /api/books/:id/random-paragraph`** — отдаёт случайный абзац из книги. Пройдём все слои: репозиторий → сервис → контроллер.

## Цель

Запрос:
```
GET /api/books/2/random-paragraph
```

Ответ:
```json
{
  "id": 421,
  "bookId": 2,
  "position": 187,
  "originalText": "She turned to the window...",
  "translatedText": "Она повернулась к окну...",
  "isTranslated": true
}
```

Если книги нет → 404.
Если в книге нет параграфов → 404.

## Шаг 1. Метод в репозитории

Открываем `artifacts/api-server/src/main/java/com/lingua/api/repository/ParagraphRepository.java`.

Добавляем метод:

```java
@Query(value = "SELECT * FROM paragraphs WHERE book_id = :bookId ORDER BY RANDOM() LIMIT 1", nativeQuery = true)
Paragraph findRandomByBookId(Integer bookId);
```

Почему `nativeQuery=true`? Потому что `RANDOM()` — функция PostgreSQL, в JPQL её нет.

Если в БД пусто — метод вернёт `null`. (Можно было бы вернуть `Optional<Paragraph>`, чтобы быть аккуратнее.)

## Шаг 2. Метод в сервисе

Открываем `artifacts/api-server/src/main/java/com/lingua/api/service/BookService.java`.

Добавляем:

```java
public Optional<Paragraph> getRandomParagraph(Integer bookId) {
    return Optional.ofNullable(paragraphRepo.findRandomByBookId(bookId));
}
```

`Optional.ofNullable` оборачивает значение, которое может быть `null`. Если `null` — получим `Optional.empty()`.

> Зачем сервис, если он просто прокси к репозиторию? Чтобы контроллер не зависел от деталей БД. Когда логика усложнится (например, исключать заголовки) — менять надо только сервис.

## Шаг 3. Эндпоинт в контроллере

Открываем `artifacts/api-server/src/main/java/com/lingua/api/controller/BookController.java`.

Добавляем метод:

```java
// ── GET /books/:id/random-paragraph ────────────────────────────────────
@GetMapping("/books/{id}/random-paragraph")
public ResponseEntity<?> randomParagraph(@PathVariable Integer id) {
    if (bookService.getBook(id).isEmpty()) {
        return ResponseEntity.notFound().build();
    }
    return bookService.getRandomParagraph(id)
            .map(p -> ResponseEntity.ok(bookService.paragraphToMap(p)))
            .orElse(ResponseEntity.notFound().build());
}
```

Что происходит:
1. Проверяем, что книга вообще существует. Нет → 404.
2. Получаем случайный параграф. Если `Optional` пустой → 404.
3. Если есть → конвертируем в `Map` (через готовый `paragraphToMap`) и оборачиваем в 200 OK.

`bookService.paragraphToMap(p)` — этот helper уже есть в `BookService`, мы его переиспользуем.

## Шаг 4. Проверка

Перезапускаем workflow `artifacts/api-server: API Server`.

Из терминала:
```bash
curl localhost:80/api/books/2/random-paragraph
```

Ожидаем JSON параграфа.

```bash
curl -i localhost:80/api/books/99999/random-paragraph
```

Ожидаем `HTTP/1.1 404`.

Готово. **Три файла, ~10 строк кода**.

## Шаблон для любого нового эндпоинта

Этот же подход работает для любого нового CRUD:

| Шаг | Файл | Что добавить |
|---|---|---|
| 1 | `repository/XxxRepository.java` | Метод доступа к БД (derived или `@Query`) |
| 2 | `service/XxxService.java` | Метод бизнес-логики, зовёт репозиторий |
| 3 | `controller/XxxController.java` | HTTP-эндпоинт, валидация, маппинг |

## Усложнение: GET с query-параметром

Хотим: `GET /api/books/:id/random-paragraph?excludeHeadings=true`. Если параметр `true` — не возвращать заголовки.

### В сервисе

```java
public Optional<Paragraph> getRandomParagraph(Integer bookId, boolean excludeHeadings) {
    Paragraph p = paragraphRepo.findRandomByBookId(bookId);
    if (p == null) return Optional.empty();
    // Если запросили без заголовков и нам попался заголовок — попробуем ещё раз пару раз
    if (excludeHeadings) {
        for (int attempt = 0; attempt < 5 && isHeading(p.getOriginalText()); attempt++) {
            p = paragraphRepo.findRandomByBookId(bookId);
            if (p == null) return Optional.empty();
        }
    }
    return Optional.of(p);
}
```

### В контроллере

```java
@GetMapping("/books/{id}/random-paragraph")
public ResponseEntity<?> randomParagraph(
        @PathVariable Integer id,
        @RequestParam(defaultValue = "false") boolean excludeHeadings) {
    if (bookService.getBook(id).isEmpty()) {
        return ResponseEntity.notFound().build();
    }
    return bookService.getRandomParagraph(id, excludeHeadings)
            .map(p -> ResponseEntity.ok(bookService.paragraphToMap(p)))
            .orElse(ResponseEntity.notFound().build());
}
```

## Усложнение: POST с JSON-телом

Хотим: `POST /api/books/:id/note` с телом `{"text": "..."}`. Сохраняет заметку (предположим, у нас есть таблица `notes`).

### В сервисе

```java
@Transactional
public Note createNote(Integer bookId, String text) {
    if (text == null || text.isBlank()) {
        throw new IllegalArgumentException("text is required");
    }
    Note note = new Note();
    note.setBookId(bookId);
    note.setText(text);
    note.setCreatedAt(Instant.now());
    return noteRepo.save(note);
}
```

### В контроллере

```java
@PostMapping("/books/{id}/note")
public ResponseEntity<?> createNote(
        @PathVariable Integer id,
        @RequestBody Map<String, Object> body) {
    if (bookService.getBook(id).isEmpty()) {
        return ResponseEntity.notFound().build();
    }
    String text = (String) body.get("text");
    try {
        Note note = bookService.createNote(id, text);
        return ResponseEntity.status(201).body(noteToMap(note));
    } catch (IllegalArgumentException e) {
        return ResponseEntity.badRequest().body(Map.of("error", e.getMessage()));
    }
}
```

Заметь: валидацию (`text is required`) сделали в сервисе, а в контроллере просто перехватили исключение. Это чище, чем дублировать проверки на двух слоях.

## Мини-упражнение

Добавь эндпоинт **`GET /api/books/count`** — возвращает `{"count": N}`, где N — количество книг.

<details>
<summary>Решение</summary>

В `BookController.java`:
```java
@GetMapping("/books/count")
public ResponseEntity<?> count() {
    return ResponseEntity.ok(Map.of("count", bookService.listBooks().size()));
}
```

Или (производительнее) добавь в сервис:
```java
public long count() {
    return bookRepo.count();
}
```

И в контроллере:
```java
@GetMapping("/books/count")
public ResponseEntity<?> count() {
    return ResponseEntity.ok(Map.of("count", bookService.count()));
}
```

`bookRepo.count()` — бесплатный метод от `JpaRepository`, делает `SELECT COUNT(*)`.

⚠️ **Осторожно с порядком эндпоинтов!** `/books/count` нужно объявить **до** `/books/{id}`, иначе Spring подумает что `count` — это `id`. На практике это не страшно (`Integer.parseInt("count")` упадёт и Spring вернёт 400), но лучше явно.
</details>
