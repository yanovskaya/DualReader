## 1. Зачем тесты

Тесты — это код, который проверяет твой код. Преимущества:
- Можно менять реализацию и сразу видеть, не сломала ли ты что-то.
- Документация: тест показывает, как метод **должен** использоваться.
- Не нужно каждый раз вручную дёргать curl.

В Spring Boot тесты уже включены — `spring-boot-starter-test` добавили в `pom.xml` ещё на [Шаге 02](02-создаём-проект.md). Если ты пропустил эту зависимость — добавь её сейчас:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>
```

Этот один starter тянет JUnit 5, Mockito, AssertJ, Spring Test, MockMvc — всё, что нам понадобится.

## 2. Структура папок

Maven ожидает тесты в `src/test/java/` (рядом с `src/main/java/`). Структура пакетов **должна совпадать** с основным кодом.

```
src/
├── main/java/com/lingua/api/
│   └── controller/HealthController.java
└── test/java/com/lingua/api/
    └── HealthControllerTest.java
```

Создай папку:
```bash
mkdir -p src/test/java/com/lingua/api
mkdir -p src/test/java/com/lingua/api/service
```

## 3. Тест контроллера через `MockMvc`

**`src/test/java/com/lingua/api/HealthControllerTest.java`** (новый):

```java
package com.lingua.api;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.test.context.TestPropertySource;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.test.web.servlet.setup.MockMvcBuilders;
import org.springframework.web.context.WebApplicationContext;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.*;

@SpringBootTest
@TestPropertySource(properties = "server.servlet.context-path=")
class HealthControllerTest {

    @Autowired
    private WebApplicationContext context;

    private MockMvc mockMvc;

    @org.junit.jupiter.api.BeforeEach
    void setup() {
        mockMvc = MockMvcBuilders.webAppContextSetup(context).build();
    }

    @Test
    void healthzReturnsOk() throws Exception {
        mockMvc.perform(get("/healthz"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.status").value("ok"));
    }
}
```

🧠 **Что нового:**

### `@SpringBootTest`
Поднимает **весь** Spring-контекст для теста (как при настоящем старте приложения, но без HTTP-сервера). Медленно (несколько секунд), зато реалистично.

### `MockMvc`
Эмулирует HTTP-запросы прямо к контроллерам, без поднятия Tomcat. Быстро.

### `@TestPropertySource`
Переопределяет `application.properties` для теста. Мы сбрасываем `context-path`, чтобы можно было обращаться напрямую к `/healthz`, а не `/api/healthz`.

### `jsonPath("$.status").value("ok")`
JSONPath-выражение: «поле `status` корневого объекта равно `ok`».

## 5. Тест сервиса (без БД)

Контроллер мы тестировали целиком. Сервис можно тестировать **изолированно** — подсунув ему фейковый репозиторий через библиотеку Mockito (она тоже уже в проекте).

**`src/test/java/com/lingua/api/service/BookServiceTest.java`** (новый):

```java
package com.lingua.api.service;

import com.lingua.api.model.Book;
import com.lingua.api.repository.BookRepository;
import com.lingua.api.repository.ParagraphRepository;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.ExtendWith;
import org.mockito.InjectMocks;
import org.mockito.Mock;
import org.mockito.junit.jupiter.MockitoExtension;
import org.springframework.jdbc.core.JdbcTemplate;

import java.util.List;

import static org.assertj.core.api.Assertions.assertThat;
import static org.mockito.Mockito.when;

@ExtendWith(MockitoExtension.class)
class BookServiceTest {

    @Mock
    private BookRepository bookRepo;

    @Mock
    private ParagraphRepository paragraphRepo;

    @Mock
    private JdbcTemplate jdbc;

    @InjectMocks
    private BookService service;

    @Test
    void listBooksReturnsAllFromRepo() {
        Book b1 = new Book();
        b1.setId(1);
        b1.setTitle("Война и мир");
        Book b2 = new Book();
        b2.setId(2);
        b2.setTitle("Идиот");

        when(bookRepo.findAllByOrderByCreatedAtAsc()).thenReturn(List.of(b1, b2));

        List<Book> result = service.listBooks();

        assertThat(result).hasSize(2);
        assertThat(result).extracting(Book::getTitle)
                .containsExactly("Война и мир", "Идиот");
    }
}
```

🧠 **Что нового:**

### `@Mock`
Создаёт «фальшивку» репозитория. Все методы по умолчанию возвращают `null` / пустые коллекции, пока мы не скажем иначе через `when(...)`.

### `@InjectMocks`
Создаёт настоящий `BookService` и подставляет в него моки.

### `when(...).thenReturn(...)`
«Когда вызовут `findAllByOrderByCreatedAtAsc()` — верни этот список». Имя метода должно **точно совпадать** с тем, что зовёт сервис (`BookService.listBooks()` зовёт именно его, а не `findAll()`).

### AssertJ
`assertThat(...).hasSize(2)` — читается как английский. Альтернатива JUnit-овским `assertEquals`. Удобнее.

⚠️ Если в твоём `BookService` сигнатура `listBooks` отличается — поправь под реальную. Идея та же.

## 6. Запуск конкретного теста

```bash
# Все тесты
mvn test

# Только один класс
mvn test -Dtest=HealthControllerTest

# Один метод
mvn test -Dtest=HealthControllerTest#healthzReturnsOk
```
