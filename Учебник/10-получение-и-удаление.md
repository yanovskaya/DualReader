# Шаг 10. `GET /books/:id` и `DELETE /books/:id`

🎯 **Цель:** можно получить или удалить конкретную книгу.

📁 **Файлы шага:**
- `src/main/java/com/lingua/api/service/BookService.java` (добавляем метод)
- `src/main/java/com/lingua/api/controller/BookController.java` (добавляем 2 эндпоинта)

## 1. Метод в сервисе

Открой `BookService.java`. Добавь метод **в конец класса** (перед `}`):

```java
@Transactional
public void deleteBook(Integer id) {
    bookRepo.deleteById(id);
}
```

🧠 **Что произойдёт?** Поскольку в SQL мы объявили `ON DELETE CASCADE`, удаление книги автоматически удалит все её параграфы.

Метод `getBook(Integer id)` уже есть с шага 06 — пользуемся.

## 2. Эндпоинты в контроллере

В `BookController.java` добавь два метода:

```java
@GetMapping("/books/{id}")
public ResponseEntity<?> getBook(@PathVariable Integer id) {
    return bookService.getBook(id)
            .map(b -> ResponseEntity.ok(bookToMap(b)))
            .orElse(ResponseEntity.notFound().build());
}

@DeleteMapping("/books/{id}")
public ResponseEntity<Void> deleteBook(@PathVariable Integer id) {
    bookService.deleteBook(id);
    return ResponseEntity.noContent().build();
}
```

🧠 **Что нового:**

### `@PathVariable`

```java
@GetMapping("/books/{id}")
public ResponseEntity<?> getBook(@PathVariable Integer id) {
```

`{id}` в пути — placeholder. `@PathVariable Integer id` — Spring сам распарсит строку из URL в `Integer`. Если не получится — вернёт 400.

### `Optional` в функциональном стиле

```java
return bookService.getBook(id)
        .map(b -> ResponseEntity.ok(bookToMap(b)))
        .orElse(ResponseEntity.notFound().build());
```

`getBook` возвращает `Optional<Book>`. Дальше:
- `.map(...)` — если внутри что-то есть, преобразовать.
- `.orElse(...)` — если пусто, использовать это.

Эквивалент:
```java
Optional<Book> opt = bookService.getBook(id);
if (opt.isPresent()) return ResponseEntity.ok(bookToMap(opt.get()));
return ResponseEntity.notFound().build();
```

### 204 No Content

```java
return ResponseEntity.noContent().build();
```

Стандарт REST: после успешного DELETE возвращают 204 без тела.

## ✅ Проверка

Перезапусти. Сначала создай книгу (если БД пустая):

```bash
curl -X POST http://localhost:8080/books \
  -H 'Content-Type: application/json' \
  -d '{"title":"Test","content":"para 1 long enough\n\npara 2 also long"}'
```

Запомни возвращённый `id` (например, 5).

```bash
# Получить
curl http://localhost:8080/books/5

# Несуществующая
curl -i http://localhost:8080/books/99999

# Удалить
curl -i -X DELETE http://localhost:8080/books/5

# Проверить, что удалена
curl -i http://localhost:8080/books/5
```

Ожидаем:
- 200 + JSON книги.
- 404 без тела.
- 204 без тела.
- 404.
